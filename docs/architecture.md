# 架构说明（公开演示版）· Architecture

> 本文档说明公开演示对应的系统架构。完整架构细节见 [architecture.svg](architecture.svg) / [architecture.png](architecture.png)。
> 背景：真实系统 IntDevTools 为 11 个 Flask 服务的研发工作台；本公开演示聚焦其中 3 个核心工具做轻量化呈现。

## 1. 分层

| 层 | 组件 | 说明 |
|---|---|---|
| 入口 | 研发工作台 / Portal | 配置驱动（config.js 一处配置，全局生效）；统一入口与状态指示 |
| 工具层 | 01 需求管理 | V 型左半：REQM → SPEC → SYRA → SYAD → SYI → SYQT；追溯矩阵；开发等级判定 |
| 工具层 | 02 设计审查（AI） | 审查规则库 + 知识库 + 引擎；AI 预审 → 逐条发现 → 人工确认 → 结果回写追溯矩阵 |
| 工具层 | 05 评价基准生成（AI） | 按产品大类 + 需求特性生成评价/测试清单；必须/推荐/参考；只出清单不落地文件 |
| 数据层 | 07 跨工具数据总线 | 业务数据中转；工具间禁止直连（生产者 → 总线 → 消费者） |
| 知识层 | 知识库（示例） | 10 标准 / 20 产品 / 40 流程；知识提供（→ 工具）与沉淀（工具 →）双向 |

## 2. 关键原则

1. **工具间业务数据统一走数据总线**，工具不直接调用对方 API。
2. **知识库是沉淀层**：读知识（provision）、沉淀知识（contribution），不做数据中转。
3. **AI 是辅助/编排**：所有 AI 生成结果（评估、审查发现、评价清单）必须经工程师人工确认后才写入与流转（human-in-the-loop）。
4. **配置驱动**：改配置即可换项目复用。

## 3. 一条链路（演示主线）

```
需求导入(REQM) ──开发等级/SYRA──▶ 数据总线 ──▶ 设计审查(AI) ──审查发现──▶ 数据总线
      ▲                                                                    │
      │                                                                    ▼
   SYQT 补充 ◀──评价清单── 评价基准生成(AI) ◀──审查发现(已确认)── 人工确认
      ▲                                                                    │
      └──────────────────── 知识沉淀(示例知识库) ◀──────────────────────────┘
```

## 4. 与真实系统的关系

- 本仓库为**公开演示**：数据全部虚构，不含真实 KHDB 内容、密钥、账号。
- 真实系统包含 11 个服务（门户 / 需求 / 审查 / 文件 / 计划 / 评价 / 认证 / 数据总线 / 进度 / 工作流 / 监控），本演示只取核心链路。
- 演示中的 AI 结果为**规则 + 示例知识库驱动的确定性模拟**；真实系统通过统一 LLM 网关调用，业务代码不直连外部 API。
